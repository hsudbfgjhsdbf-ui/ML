## Sample Response
`api/sample_response.json` — generated by hybrid pipeline
Contains:
- claim_id
- model_version
- fraud_probability (0-1)
- fraud_prediction (0/1)
- anomaly_score
- document_validation_status (PASSED/FAILED/NEEDS_REVIEW)
- policy_validation_status
- risk_category LOW/MEDIUM/HIGH
- recommended_decision APPROVE/FLAG_FOR_MANUAL_REVIEW/REJECT_OR_ESCALATE
- key_risk_signals []
- positive_evidence []
- missing_or_inconsistent_info []
- explanation (human-readable)
- evidence_references [{text, source, score}]
- timestamp ISO8601
- disclaimer

## Endpoint Design (FastAPI Example)
```
POST /predict
Body: claim JSON + optional document list
Response: structured result JSON

GET /health
Response: {"status":"ok","model_version":"hybrid_v1.0"}

POST /validate_documents
Body: {claim_id, document_paths}
Response: document validation JSON
```

## Error Handling
- 400 invalid schema -> missing fields error list
- 404 claim not found (if ID lookup)
- 500 model not loaded -> NOT_EXECUTED reason
- Never expose stack trace or PII

## Security
- API key via header, not in code
- Rate limiting future
- No external VLM/LLM call unless ENABLE_EXTERNAL_API_CALLS=true
- Log audit without PII

## Frontend Display Requirements
- Show risk category color (green/yellow/red)
- Show explanation, key risks, positive evidence
- Show document validation errors, missing docs
- Show model version, timestamp
- Show disclaimer prominently
- Mandatory human reviewer checkbox for REJECT_OR_ESCALATE
- Appeal/correction mechanism link

## Reproducibility
- Configurable thresholds via config.yaml
- Model artifacts in data/processed/artifacts
